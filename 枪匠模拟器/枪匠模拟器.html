数据：《灰区战争》0.5.0 资产（与《物品产出查询》同源）· 87 把枪 · 1337 件配件 · 数值快照 2026-11-17
槽位不是写死的：枪身给出的根槽 + 已装配件开出来的新槽，实时长出来。 某个槽位的候选件 = 全库所有「占用该接口」的配件（不再限于官方预设配过的组合）。
判定依据（2026-11-16 实测校准）
  1. 槽位 = 枪身声明的根槽 + 已装配件开出的新槽（装护木长出导轨、装上机匣长出 5 个枪管口）。
  2. 谁占哪个槽按资产目录定向，不取 socket 表的第一个 —— 那张表是字母序， 直接取会系统性错位（`Stock_M700HS…` 排头是 `Barrel.M700.Heavy`、`Stock_Ar15ArchangelCheekRiser` 排头是 `Handle.AR15`）。 目录定向后，候选池里「类别不符」的件从 6% 降到 0%，孤儿件从 8.8% 降到 1.2%。
  3. 「基础功能部件」（缺了游戏报 `MissingBaseFunctionalPart`）按三条判： 类别在必需表里 · 槽名末段不是附件词（Cover/Rail/Pad/Riser…）· 候选件不是清一色「盖」。 同类多个槽只算一件 —— AUG 的 14/16/20 吋枪管、M700 的 Heavy/Standard/Triangle 是规格任选其一， 不是要全装。例外：`Handle.AK`（AK 系拉机柄）不必需，其余武器的拉机柄都算基础件。 87 把枪装满后零误报（校验脚本 `check_required_fill.py`）。
  4. 互斥 = 去掉末段后父路径相同（`Barrel.AUG.14/16/20`、`Receiver.AK.Cover/Rail/Zenitco`、 `Barrel.AR15.14/16/18/20`）。下拉里这些候选标红并注明顶掉谁；选中会自动卸下旧的。 反例：`Mount.AK` 与 `Mount.Barrel.AK` 父路径不同 → 两个镜座可共存；枪托与枪托垫是父子 → 不互斥。
✅ 已实测：AK-74N 拆掉枪托 → 不可用；拆掉导气管 → 不可用； AK 没有拉机柄照样可用（只有 AK 这样）。 🟠 其余（机匣 / 枪管 / 握把 / 套筒 / 缓冲管 / 护木）按 socket 类型 + 用户口述判，待逐项实测校正。
改枪码只记录「哪把枪 + 装了哪些件」，不含数量与耐久。
这份模拟器读的是游戏自己的装配结构
① 每件配件资产里带一串 Socket.*：第一个是它插在哪，其余是它开出来的新槽 （例：护木占用 Socket.Handguard.AK.Ratnik，同时开出 8 个 Rail.* 导轨， 前握把 / 镜座 / 战术设备 / 手电都挂在这些导轨上）。
② 因此「装了护木才出现前握把槽」是自动的 —— 不用人工维护依赖表。
③ 红色行 = 该槽属于「基础功能部件」但没装（游戏内会显示缺少基础功能部件，武器不可用）。 拉机柄属基础件，但 AK 系例外（AK 的拉柄与枪机框一体，那个槽只装外观件）。 这份清单是按 socket 类型 + 实测推的，逐枪可能不同，实测可修正。
④ 候选件里标红的那几件 = 装上它会连带卸掉别的件（它的接口不在你当前配置提供之列）。
⑤ AUG 的护木与前握把是「二选一」：前握把槽（ForegripAug）由 AUG 枪管开出、 不挂在护木上，两者装一个就不会报缺护木（用户实测 2026-11-16）。
⑥ 修正值是满耐久标称值，线性叠加未验证 ⚪。
