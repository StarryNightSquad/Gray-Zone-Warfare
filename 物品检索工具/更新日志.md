## [0.17.4] — 2026-11-16

### 三张卡校正「4 值枪托」，并纠正一条错误判据

用户实测三张卡：

| 件 | 卡面 | 我们原来写 |
|---|---|---|
| PRS GEN3 枪托 | **只有**后坐力控制 +15.0% | 后坐+15%（✅ 本来就对） |
| G36 折叠枪托 | 后坐力控制 +3.0%、人体工学 +3.0% | 后坐-5%（❌） |
| AK-74N 木制枪托 | **一行修正值都没有，只有耐久度** | 后坐-7%（❌） |

三张卡把「缺项前移」拍得很清楚：同为 4 值，后坐可以落在 v[3]（PRS）、也可以落在 v[2]（G36），
还有两项都不该出的（AK-74N）。现在改为：

- **后坐** = v[3] 若为正，否则 v[2] 若为正，两个都不正就不出行
- **工效** = v[0]，且必须为正

三张卡逐一对上（15 / 3+3 / 无）。受影响 16 件：G36 与 G3 折叠托共 6 件由「后坐-5%」变「后坐+3% · 工效+3%」，
木托一族 10 件由「后坐-7%」变**不显示修正值**。

### 顺带纠正：后坐力控制**可以是负数**

同一批卡里，Z17 CITADEL 套筒（Glock 17）卡面是「后坐力控制 **-4.0%**、装填速度 +6.0%」——
证明负后坐是游戏真实存在且会显示的值。我们原来那版「后坐为负就是读错」的推断**作废**，
套筒 4 值的显示（后坐-4% · 装填+6%）本来就是对的，未改动。

## [0.17.3] — 2026-11-16

### 修：M-LOK AFG 的「后坐力控制」显示成 -8%

用户实测卡：**M-LOK AFG（豺狼连队）后坐力控制 +20.0% / 人体工学 +5.0%**，
我们页面写的是「后坐-8% · 工效+5%」。

原因在**取值规则**，不在数据 —— 0.5.0 与 0.5.1.1 的浮点块完全相同
（`[4.2, 5.0, -8.0, 20.0]`，逐字节一致）。4 值前握把其实有**两种布局**，
差的只是「卡上不显示的那一项」插在哪：

| 件 | 浮点块 | 工效 | 隐藏项 | 后坐 |
|---|---|---|---|---|
| AFG-2 | `[4.2, 20, 5, -8]` | v[1]=20 | v[3]=-8 | v[2]=5 |
| M-LOK AFG | `[4.2, 5, -8, 20]` | v[1]=5 | v[2]=-8 | v[3]=20 |

原来一律按 AFG-2 的布局取 `v[2]` 当后坐，M-LOK AFG 就取到了隐藏项 -8。
现在改成「v[2] / v[3] 里**为正的那个**才是后坐」（全库 9 件 4 值前握把，
5 件正项在 v[2]、4 件在 v[3]，没有两个都正的）。

受影响的件：M-LOK AFG（3 个配色，后坐 -8% → +20%）、BCM MLOK 垂直握把（2 个，-6% → +20%）。
AFG-2 一族本来就是对的，不受影响。

## [0.16.3] — 2026-11-16

### 补 57 件配件的重量与价格（尾部「少 1 字节」的变体）

有一批物品的资产尾部结构与常规不同：末尾是「等级 u8 + `0` + 4B」（5 字节），
而不是「等级 u8 + 标志 u8 + 4B」（6 字节），于是价格落在 `n-11` 而不是 `n-10`，
`read_stats()` 在常规位置读到 0，整条被判为「解析失败」。

已知例子：`Handle_SteyrAug`、`Mag_Pmag30ArM4FDE_30Rnd_300Aac`、
`MP_Mag_Pmag30ArM4FDE_30Rnd_556x45_M855_L2`。

**修法**：常规位置失败时兜底扫描 `n-14 .. n-6`，要求「价格后面恰好剩 5 或 6 字节、
且紧跟的等级字节 ≤ 6」。**只在失败时启用** —— 离线对比 1237 件原本能读到的值，零变化。

补上的都是基础件：

| 件 | 重量 | 价格 |
|---|---:|---:|
| `Stock_Ak74NWooden`（AK-74N 木制枪托） | 0.45 kg | $170 |
| `Muzzle_Mp5MuzzleCap`（MP5 枪口帽） | 0.05 kg | $34 |
| `Stock_M14EBRStock` | — | $2550 |
| `Sight_DPMicro` | 0.098 kg | $900 |

### 机制：任务挂在哪个商人资产里，就解锁那个商人卖的整枪

这是「任务在一个商人这儿、东西在另一个商人那儿」的真相。证据：

- **手艺人**资产引用 3 条 `Epic_Labrat`（`_01`/`_02`/`_04`），而它卖的整枪里「非 Stock 解锁」的
  恰好也是 3 把（FAMAS / UMP / G3 默认款）—— **3 : 3**
- **食腐鸟**资产引用 3 条（`Epic_Gunny_03` / 无编号 `Epic_Labrat_Quest` / `Epic_Labrat_09`），
  非 Stock 整枪也正好 3 把（AUG 默认款 / G36 / AUG A3）—— **3 : 3**

比如「空中毒枭」是**炮军士**的史诗任务链，但它挂在**食腐鸟**的资产里 → 完成后解锁的是食腐鸟的 AUG A1。
玩家在炮军士那边接的任务，东西却要去食腐鸟那儿买，就是这么来的。

**自洽验证 6/6**：这 6 把解锁物的整枪预设（`IS_WP_Famas_Default` / `IS_WP_UMP_Default` /
`IS_WP_G3_Default` / `IS_WP_Aug_Default` / `IS_WP_Aug_A3` / `IS_WP_G36_L2_02`）
全部能在对应商人的商品池里找到，没有一把落空。

### 一个必须说清的局限

**「哪条任务对哪把枪」在客户端没有逐条绑定。**
商人资产里商品是一段连续的字符串池、任务引用是另一段，两者无法配对（逐字节确认过）。
所以：24 条 Stock 的解锁物是从**任务名**直接取的（硬数据），
6 条剧情的是**用户对照游戏实测给的**，不是推出来的。

## [0.12.2] — 2026-11-15

### 确认：耐久度是统一乘子（正值降、负值也向 0 靠）
用户提供 **寻血猎犬的M-201C套筒**（`Slide_M201CSlidePsycho`，耐久 **80.4%**）卡面：
后坐力控制 **+0.4%**、装填速度 **−1.6%**。对应值块 `[8, 2, -6]` 的标称值是 后坐 +2 / 装填 −8：

```
+2 × 0.20 = +0.40   ✅
−8 × 0.20 = −1.60   ✅
```

两项比值都精确落在 **0.20**（考虑 1 位小数舍入，s ∈ 0.194–0.206）。另一个端点是 **s(100%) = 1**
（M700 抑制枪管卡耐久 100%，数值与值块逐位相等）。

→ **「耐久降低后负值反而上升」不需要单独规则**：乘一个小于 1 的系数，正数变小、负数也变小（即向 0 靠近），
本来就是同一个现象。用户听到的反馈由此得到解释。

**曲线还没定**：只有两个端点能拟合出无数条。已排除 `s=dur`(0.804) / `s=dur²`(0.646) /
`s=(dur−60)/40`(0.51) / `s=(dur−75)/25`(0.216→会算出 1.73 而卡面是 1.6)。
现存的「线性跌 s=1−4.08(1−dur)」与「幂律 s=dur^7.5」都成立，但都意味着耐久掉到七八成属性就所剩无几。⚪
→ 需要同一件配件在 ~95% / 60% / 30% 各一张卡就能定形。详见 `配件耐久度与数值.md`。

页面侧：物品页修正值标签的 tooltip 补上说明「这是满耐久（100%）的标称值，耐久下降时按比例缩小」。

### 修正：3 值套筒补上「装填速度」（12 件）
这张卡同时钉死了 3 值套筒的字段顺序：**`[装填(存正显负), 后坐, ?]`**。
`寻血猎犬 [8,2,-6]` → 装填 −8 / 后坐 +2 ✅；`N17 Reptile [-10,4,-6]` → 装填 +10 / 后坐 +4 ✅。

旧版**只出后坐**，理由是「2 值套筒 `[8,-7]` 卡上只有耐久度，所以 `v[0]` 不是装填」。
**这个推理是错的** —— 2 值套筒是另一种形态，本来就没有装填字段，不能拿来否掉 3 值。
现在全库 12 件 3 值套筒都补上了装填速度行，显示顺序统一为「后坐 → 装填」（与游戏卡一致）。
