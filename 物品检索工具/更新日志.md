# 更新日志

Gray Zone Warfare **物品产出查询** —— 一个单文件、纯离线的查询页（`物品产出查询.html`），
配套一套从游戏资产里解出来的索引（`Index/`）。

- **数据基线**：GZW 0.5.0（manifest `4970906435234985650`）
- **页面**：双击 `物品产出查询.html` 即可用，无依赖、无联网
- **版本号只跟踪工具与数据本身**，与游戏版本无关
- 编号规则见 [`物品产出查询_版本记录.md`](物品产出查询_版本记录.md)：MAJOR 破契约 / MINOR 加东西 / PATCH 修东西

---

## [0.9.0] — 2026-11-15

### 新增
- **配件数值（重量 / 价格）**。用 0.5.0 的 AES key 全量导出 `Items/WeaponParts/**` 后，
  从配件资产尾部的 struct 里读出两个数值：1397 件入库（`Index/part_stats.tsv`）。
  重量 0.001–2.7 kg（中位 0.192），价格 8.5–6,120（中位 374）。
- 预设卡新增「整套 **4.80 kg** · **$9630**」合计条；配件表加 `kg` / `$` 两列，末行带合计。
  `MP_` 预装弹匣没有独立资产，重量回退到弹匣本体。

### 未解
- 人机工效 / 后坐 / 精度 / 初速修正**没有解出来**。这些也在资产尾部（`01 00 00 00` 之后那 3–4 字节），
  但客户端没有 usmap、exe 里也没有 UPROPERTY 名，无法确定哪个字节对应哪一项 —— **宁缺勿错**，没有猜。

### 修复
- **钥匙页来源重复显示**。地点类的敌人来源（`地点·FishingVillage·钥匙（首领）`）被旧代码压成
  「敌人·地点」，随后又被据点信息覆盖成「邦帕首领、任务需求」，于是一把钥匙的三条不同渠道
  （敌人 / 任务A / 任务B）渲染成三个一模一样的标签。
  现在改为真实标签（`敌人·邦帕首领`、`任务需求·邪教生意`、`任务需求·LabRat 19`），
  据点信息只进悬停提示，不再改写渠道名。全库校验：**0 个物品存在重名来源**。

## [0.8.1] — 2026-11-15

### 修复
- **13 个弹匣不再显示资产 ID**。`Mag_G36_30Rnd_556x46_M855` 这类变体在本地化表里查不到，
  但名字就在资产 ID 里：把 `Mag_<枪型>_<N>Rnd` 当核心键回官方名表找同核心条目（取最短＝基础款），
  再补弹种 → `G36 5.56x45mm 30发弹匣（M855）`。
- 回查前先纠正客户端自己的口径拼写错误：`556x46` → 5.56x45、`762x52` → 7.62x51。
- `PPN10` 对 `Ammo_Pp7N10_545x39` 用后缀匹配对不上，改为去掉数字再比（`ppn`）才唯一命中。

### 新增
- **弹匣通用性标签**：一只弹匣被 ≥2 个枪族预设用过就标出来（17 只），
  如 `PMAG 30发` = M4A1 / DDM4 / MCX 共用 —— MCX 装 AR-15 弹匣不是配错，是通用件。
- 产物 `Index/_mag_alias.json`（13 条补名）、`Index/_mag_compat.json`（110 只弹匣 → 枪族）。
